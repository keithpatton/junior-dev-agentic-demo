# Glossary

## Agentic builder

A developer who shapes outcomes, context, constraints, architecture, feedback, and evidence while agents perform increasing amounts of implementation work.

Avoid using it to mean “a person who delegates everything and stops understanding the result.”

## Challenge

An evidence-seeking attempt to find missing assumptions, contradictions, boundary failures, or unproved claims.

Avoid treating rhetorical disagreement or repeated generation as challenge.

## Context spine

The small, versioned set of sources that preserves the system’s current meaning, rules, language, and direction.

Avoid using it as a synonym for every document in the repository.

## Evidence

An observation that can prove, refute, or leave a claim unresolved: a source citation, contract, test result, browser behaviour, trace, metric, or explicit human decision.

## Graph engineering

An emerging, unsettled label for designing explicit agent/task/workflow topology: nodes, allowed transitions, shared state, branches, gates, retries, and stop conditions.

In this repository the planning lifecycle is already a small explicit graph. No graph framework is required to benefit from it.

## Planning trail

The append-only sequence of intake, plan revisions, reviews, approval, execution notes, and evidence for one material task.

## System seam

A boundary where data, control, ownership, or assumptions pass between components or stages. Seams are high-leverage review points because one local decision can affect several downstream behaviours.
