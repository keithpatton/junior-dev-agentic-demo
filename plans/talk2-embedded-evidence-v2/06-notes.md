# Talk 2 embedded-evidence revision — durable notes

- Evidence is most legible on stage when it is condensed into the deck and accompanied by a small repository path, rather than shown through repeated application switching.
- The practical lifecycle is not the final thesis. It is the operating discipline through which the audience can understand the emerging agentic-builder role.
- “The scarcity is shifting” is safer and more accurate than claiming implementation correctness is completely solved.
- Vertical and horizontal describe fields of attention: vertical creates product; horizontal creates trust. The role requires awareness of both without pretending one engineer replaces specialist expertise.
- The web application is a light result reveal. It is neither the proof nor the punchline.
- Embedding artifact meaning is not enough: the audience must also see a deliberate visual change that signals “inspectable Markdown.” Pair each conceptual phase with an excerpt rather than translating every artifact into ordinary slide cards.
- A single small Markdown context artifact communicates the KISS intent better than a parade of separate lifecycle documents.
- Introduce the three outer phases with equal visual weight; highlighting one phase on the overview slide falsely implies that the talk has already entered it.
- Show the inner mechanism as a compact adversarial loop—propose, challenge, accept or revise—and use the Socratic visual as atmosphere rather than adding explanatory box copy.
- After each phase model, show a representative view of the activity: a human/agent discussion for ingestion and an agentic propose/challenge/refine trace for planning. Keep internal framework names out of the audience-facing story.
- Use the same Socratic activity grammar for implementation: execution agent, challenge agent, fix issues, then a human deployment gate.
- Let the vertical/horizontal synthesis become visual rather than another comparison: interwoven threads form a stronger engineering mind.
- Close by returning to the earlier “what will you build when code is no longer the bottleneck?” language and the builder-before-the-tree image; express the provocations in the agentic-builder vocabulary used throughout the talk.
