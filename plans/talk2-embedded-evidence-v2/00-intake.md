# Talk 2 embedded-evidence revision — intake

## Intended outcome

Revise the existing 30-minute *Beyond the Prompt* deck so an early-career developer can follow one practical agentic engineering loop without the presenter repeatedly leaving PowerPoint.

## Human decisions

- Keep the existing visual identity and the line “Love the context more than the code.”
- Make the false-confidence risk explicit near the opening.
- Use one canonical lifecycle: interrogate → plan → challenge → approve → build → challenge → prove → remember.
- Do not use the “TAF” name in the audience-facing deck.
- Embed concise Markdown-derived evidence inside slides; do not show code.
- Use the working web application only as an optional final reveal.
- End with memorable provocations a developer can use while staying inside the loop.
- Make vertical product delivery and horizontal system strengthening a central visual argument: both are needed immediately in agentic work.

## Constraints

- Preserve the current PowerPoint as the visual source and export a revised copy.
- Keep the spoken story within 25:30 and reserve 4:30 for questions.
- Evidence examples must be truthful summaries of repository-owned artifacts and carry a small repository path.
- Avoid editor screenshots or dense Markdown pages that would be unreadable in a room.

## Decisions delegated to implementation

- Exact slide count and mapping to existing slide patterns.
- Which repository excerpts best carry each consequential moment.
- The precise visual composition of the vertical/horizontal model.
- Timing adjustments that preserve the approved talk outcome.
