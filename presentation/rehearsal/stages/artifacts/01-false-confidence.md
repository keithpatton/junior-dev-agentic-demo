# Why App A creates false confidence

App A is coherent, attractive, and usable. That is precisely why it is useful evidence.

1. **It solved the request, not the outcome.** It stores applications, but it does not decide what the junior developer should do next.
2. **It hid a trust boundary.** The application object, including free-text notes, crossed persistence and export boundaries as one convenient blob.
3. **It had checks, not proof.** A successful load and a few interactions did not establish the product promise, privacy behaviour, or recovery behaviour.

The problem is not that the agent wrote poor code. The problem is that nobody had yet done enough engineering around the code.
